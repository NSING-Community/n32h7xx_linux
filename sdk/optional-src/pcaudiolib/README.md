# pcaudiolib with a TinyALSA backend

pcaudiolib is the audio output layer espeak-ng uses when it is built with
`USE_LIBPCAUDIO=1`.  Upstream speaks to PulseAudio, ALSA, QSA and OSS.  This
board has none of those four: its whole ALSA userland is TinyALSA
(`libtinyalsa.a` plus `tinyplay`/`tinycap`/`tinymix`), and there is no
`libasound`, no PulseAudio daemon, and no `/dev/dsp`.

So the port adds one backend, `tinyalsa.c`, and builds the library out of the
upstream sources plus that file.  With it in place espeak-ng can open the
board's PCM device and write to it directly, instead of writing a WAV that
somebody else has to convert and hand to `tinyplay`.

## What the backend has to do, and why

The board's I2S DAI (`kernel/sound/soc/nsing/n32h7xx-i2s.c`) accepts seven
discrete rates and **exactly two channels**:

| property | accepted |
| --- | --- |
| rate | 8000, 11025, 16000, 22050, 32000, 44100, 48000 (`SNDRV_PCM_RATE_8000_48000` — a mask, not a range) |
| channels | 2, always (`.channels_min = .channels_max = 2`) |
| format | S16_LE only |

espeak-ng always synthesises 22050 Hz **mono** S16.  22050 is one of the seven,
so the rate is fine and nothing has to resample it.  The channel count is not
fine, and that is the whole reason this backend exists:
`n32_hw_params()` has an explicit `params_channels(params) != 2 → -EINVAL`, so a
mono open is refused before a single frame is written.

Therefore `tinyalsa_write_frames()` widens.  A mono frame is one 16-bit sample;
a stereo frame is two of them at the same time; the bytes are duplicated into a
scratch buffer and written at the same rate.  **There is no resampler**, because
there is nothing left to resample — that is what the DAI change removed.

The scratch buffer is a fixed-size array inside `struct tinyalsa_object`, not a
`malloc` sized from the caller's `bytes` argument.  On this NOMMU target every
`malloc` is its own physically-contiguous mapping rounded up to a power of two
of pages (`mm/nommu.c` → `alloc_pages_exact()`), so a write-sized allocation
would fail under fragmentation for no reason at all.  Fixed 1024 frames × 2ch ×
2B = 4 KiB, same period size `tinyplay` uses.

## What the upstream checkout looks like

This port uses upstream pcaudiolib at commit `d6a6b00aa4334b461c1a09c27b6c681eaac8da8a`.

**That checkout is not pristine.**  A backend cannot be added from outside the
library — `audio.c` decides which backend to use and `audio_priv.h` declares
them — so the port patches both, plus `Makefile.am` so the file is in the
distribution.  Three hunks, recorded at:

    pcaudiolib-tinyalsa-backend.patch

Unlike espeak-ng (which must stay byte-unmodified, see
`sdk/optional-src/espeak-ng/README.md`), patching pcaudiolib is fine: it is a
separate GPL-3 project and the patch is shipped in the same release tree.  The
corresponding source for the built library is therefore **this directory plus
that patch plus the upstream commit above** — see `sdk/optional-src/pcaudiolib/`.

The delta is deliberately written in upstream's own idiom, so it would survive
as an upstream patch: the new backend is guarded by `HAVE_TINYALSA` exactly the
way the four vendor backends are guarded by `HAVE_ALSA_ASOUNDLIB_H` and friends.
`audio.c` calls `create_tinyalsa_object()` unconditionally next to the four
existing calls, and `tinyalsa.c` compiles to a `return NULL` stub when the macro
is absent.  A normal autotools build with no TinyALSA still links.

## config.h

Upstream's `config.h` is generated by autoconf, which probes the *build host*
for ALSA / PulseAudio / QSA / OSS headers.  This directory's `config.h` replaces
it and defines **none** of those — that is what makes all four vendor backends
take their stub arms.  The only thing it defines is `HAVE_TINYALSA`.

The four vendor `.c` files are still compiled even though all four are stubs:
`audio.c` calls all of them unconditionally, so their symbols must resolve.

`-I$(PORT)` must come before everything else on the compile line, or this
`config.h` is not the one found and every backend silently compiles out.

## Building

Prerequisite: TinyALSA's archive, which is not built here.

    make -C sdk/optional-src/pcaudiolib SRC=/path/to/pcaudiolib TINYALSA=/path/to/tinyalsa

Output goes under `out/work/pcaudiolib/cross/`:

    lib/libpcaudio.a              <- what espeak-ng links
    lib/libpcaudio.so             <- `make shared`, optional
    obj/                          <- objects, obj/pic/ for the -fPIC set

`make check` prints the archive members and fails if `libpcaudio.so` has a
`TEXTREL` segment.  The `.so` is linked from a separate `-fPIC` object set for
exactly that reason.

## Static or shared?

`libpcaudio.a` is what espeak-ng links, and that is a deliberate deviation from
the "build libpcaudio.so" shape this port was originally scoped as:

* the board has `libtinyalsa.a` only — there is no `libtinyalsa.so` for a
  loader to find, so a shared `libpcaudio.so` has to fold TinyALSA in anyway;
* espeak-ng here is already a single self-contained static binary;
* a no-MMU loader on a ~22 MB board gains nothing from one more shared object.

`make shared` still exists and still folds TinyALSA in, so a third-party
pcaudiolib program can link `-lpcaudio` and make sound on this board without
touching espeak-ng.  That was the other half of the original intent; it is
built and checked but nothing on the board uses it yet.
